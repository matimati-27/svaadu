# Kitchen Talk — setup (≈45 min)

(For adding the Hindi version, see `.setup-hindi.md`.)

```
kitchen-study/
├── index.html            the site (don't need to touch)
├── config.js             ← settings: Apps Script URL, video, question files
├── strings.js            ← all on-screen text, per language (te, hi)
├── media/
│   ├── mascot.png
│   └── recipe.mp4        ← PUT YOUR VIDEO HERE (exact name)
├── questions/
│   ├── te/q1.m4a … q5.m4a  ← PUT YOUR TELUGU QUESTION RECORDINGS HERE
│   └── hi/q1.m4a … q5.m4a  ← (optional) Hindi ones
└── apps-script/Code.gs   the receiver you paste into Google
```

## Where the answers end up
In **your** Google Drive (respondents never need to sign in to anything):
- Folder **Kitchen Talk Recordings** → one subfolder per respondent (e.g. `R-7KQ2MX/`) with files like `R-7KQ2MX_te_Q03_q3_groceries.webm`.
- Sheet **Kitchen Talk Responses** → tab *Respondents* (one row per person: age, gender, mother tongue, … , how many answers arrived) and tab *Recordings* (one row per answer, with a link to the file).

Nothing respondents record goes to GitHub.

---

## 1. Google side (10 min)
1. Go to **script.google.com** → *New project*. Delete what's there, paste all of `apps-script/Code.gs`, press Ctrl+S.
2. In the toolbar's function dropdown pick **setup** → **Run**. Approve permissions. Google will say *"Google hasn't verified this app"* — that's because it's your own script: click **Advanced → Go to (project name) (unsafe) → Allow**.
3. Open **View → Execution log**: it prints the links to your new folder and sheet. Bookmark both.
4. **Deploy → New deployment** → gear icon → **Web app**. Set *Execute as:* **Me**, *Who has access:* **Anyone** → **Deploy**. Copy the **Web app URL** (ends in `/exec`).
5. Paste that URL into `config.js` at `appsScriptUrl`.

(If you ever change Code.gs later: Deploy → Manage deployments → ✏️ → Version: *New version* → Deploy. The URL stays the same.)

## 2. Your media (15 min)
**Questions:** record each one on your phone's voice recorder (quiet room, phone ~20 cm away). Save as **.m4a or .mp3** — *not* WhatsApp voice notes (.opus doesn't play on iPhones). Name them exactly `q1.m4a … q5.m4a` and put them in `questions/te/`. Order:
1. What did you have for lunch today? How did you make it?
2. What did you last order from a restaurant? What goes into it?
3. If I were going to buy your groceries right now, what would you tell me to get?
4. What do you need to make halwa?
5. Explain the recipe from the video, as if you were teaching someone who's never made it.

If you use .mp3, change the extensions in `config.js` to match. To add/remove a question, add/remove a line there.

**Video:** must be **.mp4** named `recipe.mp4` in `media/`, ideally under 50 MB (GitHub refuses files over 100 MB). To shrink it:
```bash
ffmpeg -i original.mp4 -vf scale=-2:720 -c:v libx264 -crf 28 -preset veryfast -c:a aac -b:a 96k recipe.mp4
```

## 3. Put it online with GitHub Pages (10 min)
1. New **public** repository on GitHub (e.g. `kitchen-talk`). Push this whole folder to it.
2. Repo **Settings → Pages** → *Source:* Deploy from a branch → `main` / `(root)` → Save.
3. After ~1 minute your site is at `https://<your-username>.github.io/kitchen-talk/`.

The repo being public means the question audio and video are public. The answers are not.

## 4. Test it yourself (10 min) — don't skip
Open `https://<you>.github.io/kitchen-talk/?lang=te` **on your phone**, ideally on one Android and one iPhone (iPhone: use Safari). Go all the way through. Then check the Drive folder and Sheet.
- The site remembers progress on a device, so to test again use a **private/incognito tab** or a different browser.
- Delete your test row(s) and test folder afterwards.

## 5. Send it
- Telugu: `https://<you>.github.io/kitchen-talk/?lang=te`
- Hindi (only once `questions/hi/` has files): `...?lang=hi`

Tell people up front: quiet place, ~15 minutes, each question is heard once and answered once.

## Notes
- Android recordings arrive as `.webm`, iPhone ones as `.m4a`. Both play in Chrome or VLC. For Praat/ELAN convert to WAV:
  `for f in *.webm *.m4a; do ffmpeg -i "$f" "${f%.*}.wav"; done`
- If someone loses internet mid-answer, the page keeps their recording and shows **Retry sending**.
- If someone reloads the page, they continue where they left off (they can't redo a finished question).
- Answers are capped at 6 minutes each (`maxRecordSeconds` in config.js).
